**Задание**

- Проект должен эффективно использовать различные области, рассмотренные в ходе курса
- Проект должен значимым образом объединять как минимум 3 технологические области (у нас больше, чем 3)

**Установка**

Недостающие сторонние модули нужно устанавливать через pip:
`pip install jinja2 werkzeug mysql-connector-python`

До запуска нужно создать БД в локальном MySQL.
Файл для инициализации БД лежит в корне проекта.

Команда запуска веб сервиса
`python anno.py`
Стартует на порту 5555.
http://localhost:5555/ - ведет прямо на админку.
http://localhost:5555/testing_get - страница для тестирования GET запросов
http://localhost:5555/testing_post - страница для тестирования POST запросов
Если предварительно залогиниться в админку, то тестовые страницы будут открываться для того же юзера.
Если не логиниться, то будет использован юзер с id=1. Его зовут test.

2 инструмента с https://palletsprojects.com/ :

Все результаты создаются в подпапке static

**Назначеие**

Сервис генерирования GIF картинок с псевдослучайным содержимым, которое завитсит от параметра.

**Использование**

До того, как пользователь сможет начать получение GIF картинок, он должен пройти аутентификацию.
Это отдельный POST запрос к веб сервису.
Клиент передает свой логин и пароль и получает аутентификационный токен, сгенерированный для определенного user id.
В дальнейшем из токена может быть выделен этот user id для проверки, кому принадлежит токен.
Токен сохраняется клиентом в глобальной переменной `window.gifMakerAuthToken`.
В дальнейшем он используется для генерации самих GIF файлов.
*Важная особенность* : секрет для генерации токена генерируется случайным образом при запуске веб сервиса.
Следовательно при перезапуске веб сервиса все выданные ранее аутентификационные токены станут невалидными.
Можно исправить заменой рандома на фиксированную секретную строку. А можно и не исправлять.

Если есть аутентификационный токен, можно делать реальные запросы на генерацию анимированных картинок.
Есть 2 возможности сделать это:
1. POST запрос. Телом запроса является JSON. Ответ - тоже "application/json".
Одно из полей ответа - это URL, по которому лежит результат.
Сам результат потом нужно подтянуть отдельным запросом.

2. GET запрос. Тела запроса нет. Параметры запроса - это параметры прямо в URL. Ответ - "image/gif".
Такой URL можно прямо использовать в качестве значения атрибута src у элемента <img>  
`let url1 = "http://localhost:5555/g?token=__TOKEN__&t=123&template=1";`
`jQuery('#demo1').attr('src', url1.replace('__TOKEN__', window.gifMakerAuthToken));`

Каждый запрос создаеть запись в БД. Это сделано для кеширования результата.
Если юзер А создает GIF картинку вида Б c параметром В, то запись об этом сохраняется в БД.
Повторный запрос от А на картинку вида Б c параметром В вернет ранее сохраненный файл, 
а не будет запускать генерацию GIF картинки заново. Это существенно ускоряет сервис.
